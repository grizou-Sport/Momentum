## Corrections et tests

Une nouvelle migration bloque les écrivains obsolètes avant toute ligne applicative ; elle ne touche aucune donnée existante. Le client transmet le contrat attendu et donne une consigne de rechargement. Les tests SQL couvrent les créations, modifications, suppressions, instructions sans ligne, absence de reçu après refus, conservation des souvenirs, lectures, accès étrangers et maintenance serveur. L’API réelle confirme le même refus avec des JWT valides, puis une écriture après mise à jour du client. Le libellé de contrat ne confère aucun droit.

La récupération du mot de passe résout maintenant la destination dans le traitement d’erreur principal. Une panne de lecture après changement ne peut plus laisser une redirection asynchrone rejetée et un faux message d’ouverture. L’écran confirme le changement et permet de reprendre la connexion avec le nouveau mot de passe.

Installation propre avec le verrou de dépendances, **211 tests réussis**, zéro échec et zéro test ignoré ; **204 fichiers statiques** construits. La recette réelle Supabase réussit dix scénarios (onze résultats Node avec la suite parente) en 171,9 secondes. Les **17 nouvelles migrations CDC** sont exécutées ; Auth, PostgREST, Storage, Edge Runtime, Vault, cron et réseau interne sont réels. Le schéma applicatif de départ reste représentatif. Le contrôle ciblé des sept tests de livraison réussit également après la distinction du chapitre 27.

- Page ouverte avant la migration : saisie d’un Moment de 80 minutes et d’un souvenir, sans effort. Après migration, tentative refusée, formulaire et texte conservés, consigne « Conserve ton texte puis recharge la page ». Relecture locale : aucune ligne pour cette tentative. Après rechargement et nouvelle saisie, une ligne de 80 minutes, RPE nul et souvenir exact est enregistrée.
- Version exacte pré-CDC `dd8b37eb72c4ddc1a255c8f4e3a3f42f9f9fcfa0`, servie avec seulement l’adresse et la clé publique de Docker remplacées : un compte fictif portant l’ancien indicateur de Passeport terminé ouvre HOME. Son formulaire historique, rempli avec des réponses explicites, affiche « Enregistrement interrompu. Réessaie dans un instant. ». Il reste ouvert avec son souvenir. La base contient zéro activité de ce compte après la tentative. Ce vieux code ne sait pas afficher la nouvelle consigne détaillée ; il ne présente pas un succès.
- Service PostgREST local réellement suspendu : YOU reste protégé et, après le délai de douze secondes, affiche « Impossible de charger ton espace pour le moment », Réessayer et un retour à la découverte. Après reprise du service et Réessayer, le même Passeport revient, sans onboarding imposé ni déconnexion.
- Déconnexion, ouverture de `you.html?section=account`, reconnexion : la destination demandée est conservée et la rubrique du compte s’affiche. Une destination externe `https://example.invalid/index.html` injectée dans `returnTo` aboutit à HOME. Les tests couvrent aussi les autres formes d’URL dangereuses et les erreurs d’accès expiré confirmées.
- Mot de passe oublié demandé dans l’interface, courriel capturé uniquement par Mailpit local, lien ouvert : le formulaire de nouveau mot de passe apparaît. PostgREST est arrêté pendant la validation ; Auth modifie réellement le mot de passe, puis la panne du profil affiche la reprise prévue. Après redémarrage, le nouveau mot de passe reconnecte le compte dans HOME. Vérification séparée : ancien mot de passe refusé (HTTP 400), nouveau accepté (HTTP 200). Aucun courrier externe ni compte réel n’est utilisé.

Les services locaux sont rétablis et le serveur affiche de nouveau les sources actuelles. Les identifiants, liens de récupération et archives restent privés. Les résultats non sensibles sont dans [le relevé](2026-09-12.client-access-results.json).
