## Concurrence PostgreSQL réelle

`validation/postgres-concurrency.mjs` utilise des connexions PostgreSQL indépendantes. PostgreSQL 17.10 a été démarré sur ce Mac sans port TCP, sur un socket privé. Chaque exécution crée puis supprime sa propre base de test. Les quinze migrations CDC sont exécutées sur les tables fictives représentatives avec les 72 clés étrangères capturées ; Auth, Storage, Vault, pg_cron et pg_net restent des adaptateurs.

Les cinq scénarios passent : reprise concurrente du même reçu, deux imports de la même empreinte, deux modifications de la même révision, dernière place d’un Moment collectif incluant l’organisateur, deux workers réclamant les mêmes fichiers à nettoyer. Les quatre premiers maintiennent la première transaction ouverte jusqu’à constater dans `pg_stat_activity` que la seconde attend réellement un verrou. Le dernier vérifie que le second worker obtient un lot vide sans attendre la transaction du premier.

La CI exécute désormais `npm test` puis `npm run test:postgres` avant le contrôle de livraison, sur un service PostgreSQL 17.6 isolé. Le contrôle CDC reste obligatoire : des tests métier réussis ne suffisent pas à publier une version non validée. Résultats locaux dans `2026-09-12.local-results.json`.

- Essais qualitatifs avec cinq personnes et revue complète des 113 scénarios. Les preuves automatisées n’ont pas été transformées en essais humains.
